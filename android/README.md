# Tactile Noise for Android (Trusted Web Activity)

This folder is the Google Play app. It's a thin Android shell, generated by Bubblewrap, that
opens the PWA at https://noise.tactile.software full-screen in Chrome. It has no app code of
its own: every sound, screen and fix ships by deploying `web/`.

## What's where

| Path | What it is |
| --- | --- |
| [`../app.config.json`](../app.config.json) | **The only place to edit** the name, description, colours, host, package ID, version and signing fingerprints. The PWA build and this project both read it. |
| `app/build.gradle` | Reads `app.config.json` at build time. |
| `twa-manifest.json`, `manifest-checksum.txt` | Bubblewrap's project file, **generated**: run `node scripts/sync-twa-manifest.mjs` after editing `app.config.json`. CI fails if it's out of date. |
| `app/src/main/res/mipmap-*`, `drawable-*/splash.png` | **Generated** by `npm run icons` in `web/` from `web/public/icons/*.svg`. |
| `app/src/main/res/drawable-*/ic_notification_icon.png` | Hand-made monochrome notification icons. Not generated. |
| `play-store/feature-graphic.png` | Play listing banner, **generated** by `npm run icons`. |
| `app/src/main/java/…` | Bubblewrap's standard launcher and delegation classes. |

> [!WARNING]
> `bubblewrap update` regenerates `app/build.gradle` and the resources. If you run it, restore
> the `appConfig` lines at the top of `app/build.gradle` and the signing block, then run
> `npm run icons` again.

## Build

Needs JDK 17 and the Android SDK (Android Studio provides both).

```sh
cd android
./gradlew assembleDebug                 # debug APK, unsigned by the upload key
./gradlew installDebug                  # install on a connected device or emulator

# Signed release bundle for Play (keystore stays outside git):
KEYSTORE_PASSWORD=… KEY_PASSWORD=… ./gradlew bundleRelease
# → app/build/outputs/bundle/release/app-release.aab
```

The keystore defaults to `android/upload-keystore.jks` (ignored by git); set `KEYSTORE_PATH`
to keep it elsewhere and `KEY_ALIAS` if it isn't `upload`. On macOS, Android Studio's Java is
at `/Applications/Android Studio.app/Contents/jbr/Contents/Home` (use it as `JAVA_HOME`).

To release a new version, raise `android.versionCode` (and `versionName`) in
`app.config.json`, run `node scripts/sync-twa-manifest.mjs`, then build. Most changes don't
need a new Play release at all: deploying the PWA updates the app.

# Google Play Store Publishing Guide

This guide walks you through publishing **Tactile Noise** (`software.tactile.noise`) as an upfront paid app on the Google Play Store using a **Trusted Web Activity (TWA)** generated via Bubblewrap.

---

## 1. Architecture & Monetization Overview

* **Engine:** Progressive Web App (Preact + Vite + Web Audio / AudioWorklet) running via Google's official [`com.google.androidbrowserhelper`](https://github.com/GoogleChrome/android-browser-helper) (v2.7.4) in this folder.
* **Package / Application ID:** `software.tactile.noise`
* **Target Web Host:** `https://noise.tactile.software` (set in [`app.config.json`](../app.config.json)).
* **Why TWA for Tactile Noise?**
  1. **Instant Web Updates:** Procedural DSP improvements, new sounds, or UI tweaks deployed to your web host are instantly available to Android app owners without waiting days for Google Play review or requiring manual app updates.
  2. **Tiny Binary Size:** The release `.aab` is approximately **3.7 MB** (compared to 15–30 MB for packaged native/hybrid apps).
  3. **Performance & Standards:** AudioWorklet and Web Audio run directly in modern Chromium with zero abstraction overhead. Background playback, media session controls, and offline caching via Service Worker function seamlessly.
* **Monetization Model (Upfront Paid App on Google Play):**
  * The app is listed as a **Paid** app on the Google Play Store (e.g., $1.99, $2.99, or $4.99).
  * Google Play gates the initial download and installation. Users pay Google before installing.
  * Once installed, launching the app icon on Android opens Tactile Noise directly without advertisements, interruptions, or in-app paywalls.
  * The public web URL remains un-gated (no login or client-side license checks required). The Google Play purchase pays for the convenience of native Android installation, home screen/app drawer presence, lock-screen media controls, and offline integration.

## 2. Digital Asset Links (`.well-known/assetlinks.json`)

For a Trusted Web Activity to run **full-screen without the browser URL address bar**, Google Chrome verifies a two-way cryptographic relationship between the website domain and the Android app signing certificate using **Digital Asset Links**.

### Current Configuration

The site's statement file, `/.well-known/assetlinks.json`, is generated by the PWA build
(`web/vite.config.ts`) from `android.packageId` and `android.sha256CertFingerprints` in
[`app.config.json`](../app.config.json). The app's own half (which site it trusts) is
generated in `app/build.gradle` from `host`.

### Google Play App Signing Note
> [!IMPORTANT]
> When you upload your `.aab` to Google Play, Google creates an **App Signing Key** managed by Google.
>
> 1. Once uploaded, go to **Release** → **Setup** → **App signing** in Play Console.
> 2. Copy the **SHA-256 certificate fingerprint** from the *App signing key certificate* section.
> 3. Add this SHA-256 fingerprint to `android.sha256CertFingerprints` in [`app.config.json`](../app.config.json), then run `node android/scripts/sync-twa-manifest.mjs`.
> 4. Deploy your website (`cd web && npm run deploy`).
>
> Until the web server serves the matching Google Play signing fingerprint, Chrome will display a Custom Tab URL top-bar fallback rather than running completely full-screen.

## 4. Google Play Console Setup Walkthrough

### Step 4.1: Developer Account & Merchant Profile
1. Log in to [Google Play Console](https://play.google.com/console).
2. If charging upfront for apps, navigate to **Settings** → **Developer account** → **Payment settings** and create a **Google Payments Merchant Profile**.
3. *Note on Paid Apps:* Under consumer protection regulations, Google will display your legal developer/business name and mailing address publicly on the store page.

### Step 4.2: Create the Application
1. Click **Create app** on the dashboard.
2. Fill in:
   * **App name:** `Tactile Noise`
   * **Default language:** English (US)
   * **App or game:** App
   * **Free or paid:** **Paid**
3. Accept the Declarations (Developer Program Policies & US export laws) and click **Create app**.

### Step 4.3: Set Price & Availability
1. In the left sidebar, navigate to **Monetize with Play** → **Products** → **App pricing**.
2. Click **Set app price** (e.g., USD $2.99). Google will automatically calculate converted prices with local taxes for all supported countries.
3. Select the countries/regions where you want the app available.

### Step 4.4: Store Listing Details
Navigate to **Grow** → **Store presence** → **Main store listing**:
* **App Name:** `Tactile Noise`
* **Short Description:** (up to 80 chars)
  > `Continuous procedural noise and nature sounds for focus, tinnitus masking & sleep.`
* **Full Description:**
  > Tactile Noise is a clean, continuous ambient sound generator inspired by Apple's Background Sounds feature.
  >
  > Unlike apps that loop short audio clips, Tactile Noise generates all fourteen sounds in real time using on-device procedural digital signal processing (DSP). You will never hear an unnatural audio loop seam, click, or repetitive pattern.
  >
  > FEATURES:
  > • 14 Handcrafted Ambient Sounds:
  >   - Noise: Balanced (Pink), Bright (White), Dark (Brown), Grey (inverse equal-loudness)
  >   - Nature: Rain, Ocean waves, Mountain Stream, Wind, Night crickets, Campfire
  >   - Travel & Machines: Box Fan, Steam hiss, Airplane cabin, Passenger train
  > • 100% Offline: Synthesizes sound entirely on your phone. No internet needed.
  > • Sleep Timer: Gentle, linear fade-out to protect your sleep without abrupt cutoffs.
  > • Hearing Safety: Volume cap and soft-knee limiter prevent sudden loud spikes.
  > • Per-Sound Tone Shaping: Customize warmth (dark ↔ bright tilt) and droplet/wave intensity.
  > • Media Controls: Notification shade and lock-screen playback controls with previous/next sound shortcuts.
  > • Zero Ads, Zero Tracking: No analytics, no accounts, no data collection.
* **Graphics:** Upload:
  * App icon: `web/public/icons/maskable-512.png`
  * Feature graphic: `android/play-store/feature-graphic.png`
  * Phone screenshots: `web/public/screenshots/phone-playing.jpg` and `phone-timer.jpg`
  * Tablet screenshot: `web/public/screenshots/desktop.jpg`

### Step 4.5: App Content Declarations (Mandatory)
In the left sidebar, go to **Policy and programs** → **App content**:
1. **Privacy Policy:** Paste your privacy policy URL (e.g., `https://noise.tactile.software/privacy.html`).
2. **Ads:** Select **"No, my app does not contain ads"**.
3. **App Access:** Select **"All functionality is available without special access"**.
4. **Content Ratings:** Start questionnaire → Category: **Utility / Productivity / Audio** → Answer "No" to violence, sexuality, offensive language, or user location sharing. Result will be PEGI 3 / ESRB Everyone.
5. **Target Audience & Content:** Select age group **13+** (or All Ages).
6. **Data Safety Questionnaire:**
   * Does your app collect or share any user data? Select **"No"**.
   * (The app stores settings only on the device; no remote data transfer occurs).
7. **Government Apps:** Select **"No"**.
8. **Financial Features:** Select **"No"**.
9. **Health Apps:** Declare as an ambient wellness/sound app, noting that it is not a medical device.

## 6. Testing & Release Tracks

### Step 6.1: Internal Testing
1. In Play Console, go to **Testing** → **Internal testing**.
2. Create a new release and upload `android/app/build/outputs/bundle/release/app-release.aab`.
3. Add your personal Google account email to the testers list.
4. Open the invite link on your Android phone and install the app to verify:
   * Continuous sound synthesis without loop artifacts.
   * Lock-screen and notification shade media playback controls.
   * Fullscreen display (once `assetlinks.json` is verified).

### Step 6.2: Closed Testing (Personal Accounts)
> [!NOTE]
> If your Google Play Console account was created as an individual account after November 13, 2023, Google requires a minimum of **14 days of closed testing with at least 12–20 opted-in testers** before applying for production access.

1. Create a **Closed testing track**.
2. Invite your test group (friends, colleagues, or community testers).
3. Keep the track active for 14 continuous days.

### Step 6.3: Production Release
Once testing is complete:
1. Navigate to **Release** → **Production**.
2. Create a new release from your verified bundle.
3. Submit for review! Google typically reviews paid apps within 1–3 business days.
